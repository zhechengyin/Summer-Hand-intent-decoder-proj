# b2 620.6 KB plan — STM32Cube.AI export

Run `run.ps1` from PowerShell using the repository environment. It exports the
fixed checkpoint, verifies ONNX outputs, calls the installed ST CLI, packages
the generated C, runs the actual compiled C on 256 fixed samples, and compiles
all five translation units for Cortex-M7. The wrapper limits each ST process
to 6 GiB private memory and 240 seconds. A failed numerical check prevents a
successful finish. It does not train, change checkpoints, or flash a board.

```powershell
cd C:\Users\fangz\Documents\Summer-Hand-intent-decoder-proj
powershell -ExecutionPolicy Bypass -File indy_loco\experiment\mingru_mixed_precision\cubeai_export\run.ps1
```

Results are in `../results/b2_cubeai_export_v1/stm32_package/`. The package
README and validation receipts describe the verified conversion and its memory
requirements. `runtime_positive_slices` is the first full successful conversion.
Earlier folders are diagnostic attempts, not deployment packages.

Source is b2 EMA, `indy_20160622_01`, fold 1, following the earlier predeclared
deployment-export example. It is not the best test fold, an ensemble, or an
average of 30 checkpoints. Input normalization and target de-normalization
remain application responsibilities; `preprocessing.json` contains this fold's
scalers and channel IDs.

The selected W8A32 plan stores nine minGRU/FFN matrices in INT8, with FP32
encoder, head, biases, state, nonlinearities and activations. Native import of
constant ONNX INT8 weights expands them to FP32 in this installed ST version.
The export instead passes the nine fixed packed matrices as application-owned
input buffers. `b2_decoder.c` hides those nine extra inputs from the caller.
All neural-network operators are generated by Cube.AI; this adapter supplies
pointers and invokes its API.

The export uses an algebraically equivalent affine prefix computation within
each 50-bin window and moves channel scale after matrix multiplication. The
resulting FP32 reassociation is checked against the original sequential W8A32
reference. It does not introduce persistent streaming. Runtime dequantization
uses unit scale and explicit output-channel scaling because the direct
per-channel runtime DQ probe failed C parity in version 10.2.0. Explicit positive
slice endpoints avoid that tool's observed off-by-one behavior for negative
endpoints; causal padding is represented directly in Conv attributes.

Host validation is numerical conversion validation, not a new test R² run or
an MCU latency result. Weight storage remains INT8/FP32, but the runtime creates
temporary FP32 weight matrices and performs FP32 GEMMs. The generated memory
schedule currently keeps substantial FP32 workspace. Board memory planning and
40 ms latency testing are separate work.
