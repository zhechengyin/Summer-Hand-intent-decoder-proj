# Indy model-ready data

Generated by
`data/processing/indy_loco/indy/prepare_indy_model_ready.ipynb`.

Artifacts use a fixed chronological, session-level split:

```text
indy/
  train/        29 sessions: 2016-04 through 2016-10
  validation/    4 sessions: 2016-12
  test/          4 sessions: 2017-01 (locked)
  session_inventory.csv
  manifest.json
```

Each `indy_*.npz` preserves one complete session using the minimal
`indy_counts_velocity_v2` schema:

- `counts`: `(96, bins)` unsmoothed M1 spike counts, `uint8`; this is the only
  model input stored in the artifact;
- `velocity`: `(bins, 2)` causal fingertip `(-x, -y)` velocity in cm/s,
  `float32`; this is the supervised target;
- scalar session, checksum, bin-width, schema, and causal-method provenance.

The canonical `M1 001` through `M1 096` channel order is validated during
processing and stored once in `manifest.json`, rather than repeated in every
session artifact. Cursor/target/position arrays, unit counts, timestamps, channel
strings, areas, and waveform snippets are not copied.

The notebook also creates `session_inventory.csv` and `manifest.json`. Generated
NPZ and manifest payloads are ignored by Git and can always be rebuilt from raw.
The split is versioned in `configs/datasets/indy_sessions.yaml`; do not randomly
move windows between folders or tune against the January test sessions.
